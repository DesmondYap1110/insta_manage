1. Architecture

1.1 Runtime topology — the five processes

The application is not a single program. Five processes must be running; four of them are long-lived services and one is the dev server for the UI. Most "nothing happens when I click download" reports trace back to one of these being down.

ProcessStart commandIf it is down
MySQLLaragon, or mysqld.exeBackend fails on startup / every request 500s
Redisredis-server.exe --port 6379API still works; jobs never start (stay pending)
Celery workercelery -A app.tasks.celery_app worker --pool=soloJobs queue up but never execute
FastAPIuvicorn app.main:app --reloadUI loads but every call fails
Vitenpm run devNo UI at all
Windows-specific Celery's default prefork pool does not work on Windows. --pool=solo is mandatory — without it the worker starts, connects, prints "ready", and then silently never executes a task.

1.2 Backend layering (and how it maps to MVC)

The backend is a layered architecture. It borrows from MVC but is not textbook MVC, because the server renders no HTML — the "view" is a separate React app consuming JSON.

LayerDirectoryResponsibility
Modelapp/models/SQLAlchemy ORM classes — the actual tables. Same role as MVC's Model.
Controllerapp/routers/HTTP endpoints. Parse/validate, call a service, shape the response. Deliberately thin.
View(none server-side)Replaced by the React SPA. This is the main divergence from classic MVC.
Serviceapp/services/Business logic: Instagram access, Playwright login, crypto, password hashing. Not an MVC concept — added so controllers stay thin and logic is reusable from Celery tasks.
Schema (DTO)app/schemas/Pydantic request/response contracts. Gives automatic validation and the OpenAPI docs.
Taskapp/tasks/Celery entry points. Own transaction + job-status bookkeeping.
Why services exist as their own layer download_posts() is called from a Celery task, never from a router. If that logic lived in the router it would be unreachable from the worker. Keeping it in services/ means the same function serves both entry points.

1.4 Database schema

The idempotency key UNIQUE(account_id, instagram_media_id) is what makes re-running a download safe — on both media_items and discovered_media. Carousel children get a synthetic id of {mediaid}_{index} so each slide is tracked separately, and share the parent post's shortcode as carousel_group_id so the UI can group them back together.

2. Design System

2.1 Where it came from

The visual language was ported from the desmondyap admin theme (C:\laragon\www\desmondyap\adm) — specifically dashboard/inc/color-dark-theme.php and inc/header-cons.php. The source is PHP + jQuery, so files could not be copied verbatim; the design decisions were re-expressed as CSS custom properties and React components.

Source (desmondyap)Destination (this app)
Hard-coded hex values across PHP includesstyles/tokens.css — CSS variables
.sidebar-d, #sb-active, #bc-divstyles/layout.css + components/layout/

Why DataTables was rewritten rather than imported jQuery DataTables takes ownership of the DOM it renders. React also owns that DOM and re-renders rows whenever state changes. The two fight, and rows detach or duplicate. The React port keeps the identical look and features (search, page-length, sorting, info line, pagination, CSV/print) without the conflict.

2.2 Token architecture & CSS layer order

Everything visual resolves to styles/tokens.css. No component file contains a raw hex colour. Import order matters and is fixed in styles/index.css:

tokens.css      ← variables — must be first
base.css        ← resets, typography, scrollbars
layout.css      ← sidebar / topbar / breadcrumb shell
components.css  ← buttons, panels, pills, forms
datatable.css   ← table, toolbar, pagination
media.css       ← gallery grid, thumbnails, modal
login.css       ← the sign-in gate

Consequence: re-theming the entire application — back office and any future front-facing page — is a single-file edit.

Column keyMeaning

The most likely DataTable mistake Omitting value on a composite cell. The column renders fine, but searching for text that is visibly on screen returns nothing — because the filter only saw row[key]. This exact bug shipped and was caught in testing (see §4.7).

3. Pipelines

3.1 Instagram login pipeline

Design constraint: the application must never receive the Instagram password. This is achieved by not building a password field at all — a real browser is opened on Instagram's own login page and only the resulting cookies are harvested.

Implementation notes worth knowing when debugging:

  • It runs in a plain Python thread, not Celery — it needs a live desktop window and 1.5-second polling, which a distributed worker cannot provide.
  • Success is detected by the presence of both sessionid and ds_user_id cookies — not by URL matching, which is brittle across Instagram's redirect variants.
  • The captured User-Agent is stored alongside the cookies and replayed on every later request. Mismatching the UA is a common cause of instant session invalidation.
  • Timeout is LOGIN_TIMEOUT_SECONDS (default 300). Closing the window early yields status closed, not failed.
  • Terminal states: connected · failed · timed_out · closed. The manager's state lives in memory, so a backend restart mid-login abandons the attempt.

3.2 Download job pipeline

POST /api/downloads/jobs
   └─ INSERT download_jobs (status=pending, progress 0/0)
   └─ task.delay(job_id) ──▶ Redis ──▶ Celery worker
                                          │
      _run_job(job_id, action) ───────────┘
        ├─ status = running, started_at = now()
        ├─ get_authenticated_loader(db)
        │     ├─ SELECT active instagram_sessions
        │     ├─ Fernet-decrypt cookie blob
        │     ├─ rebuild requests.Session (cookies + stored UA)
        │     └─ loader.test_login()  # raises if session died
        ├─ action(db, loader, account, progress_cb)
        │     └─ per item:  resolve URL → context.get_raw() → write bytes
        │                   → probe dimensions → UPSERT media_items
        │                   → progress_cb(i, total) → COMMIT
        │                   → sleep(DOWNLOAD_REQUEST_DELAY_SECONDS)
        └─ status = success | failed(+error_message), finished_at = now()
Job typeWhat it iterates
sync_profileProfile metadata + avatar only. Cheapest; use it to test connectivity.
download_postsprofile.get_posts() — every post, expanding carousels
download_reelsSame, filtered by _is_reel()
download_storiesget_stories() → story.get_items() (24h window only)
download_single_postOne shortcode. Best first end-to-end test.
Why context.get_raw() rather than plain requests It reuses Instaloader's authenticated session and its retry/back-off handling, so the download inherits polite behaviour toward Instagram's rate limits instead of reimplementing it badly.

3.3 Media-type resolution

A single Instagram post can produce one row or twelve. The branching in _post_to_pending():

if post.typename == 'GraphSidecar':      # carousel
    for i, node in enumerate(post.get_sidecar_nodes()):
        type = CAROUSEL_VIDEO if node.is_video else CAROUSEL_IMAGE
        id   = f'{post.mediaid}_{i}'      # synthetic per-slide id
        url  = node.video_url if node.is_video else node.display_url
elif post.is_video:
    type = REEL if _is_reel(post) else POST_VIDEO
    url  = post.video_url
else:
    type = POST_IMAGE
    url  = post.url
Known limitation — reel detection Instaloader's Post class exposes no product_type property, and Instagram's timeline GraphQL response does not reliably include one. _is_reel() reads post._node.get('product_type') == 'clips' when present and otherwise classifies the item as post_video. "Download Reels" may therefore under-count. If reels appear missing, this is the first place to look — not the network layer.

3.4 Storage layout & metadata capture

media/
└── {username}/
    ├── profile_pic.jpg
    ├── post_image/     20240115_142233_CxYz123AbCd.jpg
    ├── carousel_image/ 20240115_142233_CxYz123AbCd.jpg
    ├── reel/
    └── story_video/

Filename pattern: {taken_at:%Y%m%d_%H%M%S}_{shortcode|media_id}.{ext}. The extension is derived from the HTTP Content-Type, falling back to the URL suffix.

Files are written byte-for-byte as served. Pillow is used only to read width/height from the in-memory buffer — the image is never re-encoded or resized. Captured per item: media type, Instagram media id, shortcode, caption, taken_at, download timestamp, path, extension, resolution, byte size, and source URL.

4.4 Inspecting state with SQL

-- Is a session connected, and to whom?
SELECT ig_username, is_active, updated_at FROM instagram_sessions ORDER BY id DESC;

-- Recent jobs with failures
SELECT id, job_type, status, progress_current, progress_total,
       LEFT(error_message,90) AS err, created_at
FROM download_jobs ORDER BY id DESC LIMIT 20;

-- What actually got downloaded, by type
SELECT a.username, m.media_type, COUNT(*) AS n, SUM(m.file_size_bytes)/1048576 AS mb
FROM media_items m JOIN tracked_accounts a ON a.id = m.account_id
GROUP BY a.username, m.media_type;

-- Rows whose file is referenced but may be missing on disk
SELECT id, file_path, file_size_bytes FROM media_items WHERE file_size_bytes IS NULL OR file_size_bytes = 0;

-- Confirm no plaintext password is stored
SELECT username, LEFT(password_hash,7) AS algo, LENGTH(password_hash) AS len FROM admin_users;
-- expect: $2b$12$ / 60

Bypassing the UI isolates backend from frontend. FastAPI serves interactive docs at http://127.0.0.1:8000/docs; log in through the UI first so the browser holds the cookie, then call endpoints from that page.

     -d "{\"username\":\"admin\",\"password\":\"...\"}"

curl -b c.txt http://127.0.0.1:8000/api/accounts

     -H "Content-Type: application/json" \

Delete the cookie jar afterwards c.txt holds a valid 7-day session token. Remove it when finished.

4.6 Frontend debugging

  • Network tab — confirm the request went to /api/... and that imm_session is attached. A 401 here means auth, not application logic.
  • Console — React surfaces key warnings and prop errors here.
  • React StrictMode double-invokes effects in development. Seeing two identical requests on mount is expected and does not occur in a production build.
  • The cookie is invisible to JavaScript by design. document.cookie returning '' is correct — verify the cookie in DevTools → Application → Cookies instead.

4.7 Case studies: three real bugs

All three passed code review and were only exposed by exercising the running application.

1 — Route collision made the Media Library unreachable The backend mounted static files at /media; the SPA also routed /media to the Media Library page. Vite proxied the path to the backend, which returned {"detail":"Not Found"} instead of rendering the page.
Detection: a screenshot showing raw JSON where the page should be.
Fix: static mount moved to /files.
Lesson: API paths and client-side routes share one namespace once a proxy is involved.
2 — Pagination silently reset to page 1 updateParam() set the requested key, then unconditionally executed next.set('page','1'). Because page changes flowed through the same helper, every page click was overwritten back to 1.
Detection: asserting the info line after clicking page 2 — expected "11 to 12", got "1 to 10".
Fix: split into updateFilter() (resets page) and goToPage() (does not).
Lesson: one helper serving two intents will eventually serve one of them wrongly.
3 — Search ignored visible text The Account cell rendered username and full name, but the column had no value accessor, so the filter only saw row.username. Searching "space" matched spacex but not "European Space Agency".
Detection: comparing result count against what was visibly on screen.
Fix: value: (r) => `${r.username} ${r.full_name}`.
Lesson: when display and data diverge, search must follow display.

4.8 Reset procedures

# Forgot the back-office password
# edit ADMIN_PASSWORD in backend\.env, then:
venv\Scripts\python -m scripts.create_admin

# Force a fresh Instagram login
UPDATE instagram_sessions SET is_active = 0;

# Clear job history (safe — does not touch downloaded media)
DELETE FROM download_jobs;

# Remove one account and everything it owns (FK cascade)
DELETE FROM tracked_accounts WHERE username = 'someuser';
# files under media\someuser\ must be deleted manually

# Rebuild the schema from scratch (DESTROYS ALL DATA)
DROP DATABASE instagram_media_manager;
CREATE DATABASE instagram_media_manager CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
# then: alembic upgrade head  &&  python -m scripts.create_admin
Rotating SECRET_KEY has two effects It signs back-office sessions and encrypts the stored Instagram cookies. Changing it logs out every admin session and makes the saved Instagram session undecryptable — a fresh browser login will be required.

Operating boundaries

This application deliberately does not implement CAPTCHA solving, 2FA bypass, private-account circumvention, or rate-limit evasion. Access is bounded by what the authenticated Instagram session is legitimately permitted to see. DOWNLOAD_REQUEST_DELAY_SECONDS exists as courtesy throttling; increasing it is the correct response to rate limiting.
